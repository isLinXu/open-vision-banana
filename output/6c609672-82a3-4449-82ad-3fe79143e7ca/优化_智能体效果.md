# Crablet 智能体（Agent）效果优化方案

## 问题

当前 Crablet 的智能体核心功能大多为**空壳实现**，无法实际执行任务。

### 1. 工作流引擎（workflow/engine.rs）

**现状**：直接返回 `Completed`，无实际执行逻辑。

**优化方案**：

```rust
// 原代码
fn run(&mut self, task: &str) -> StepResult {
    // 空壳实现，直接返回完成
    StepResult::Completed
}

// 优化为：DAG 拓扑排序 + 并行执行
fn run(&mut self, task: &str) -> StepResult {
    let dag = build_dag_from_config(&self.config);
    let sorted = topological_sort(&dag);
    
    // 并行执行无依赖节点
    let mut handles = Vec::new();
    for node in sorted {
        if node.in_degree == 0 {
            let handle = tokio::task::spawn_blocking(move || {
                execute_node(node)
            });
            handles.push(handle);
        }
    }
    
    // 等待所有并行任务完成
    for handle in handles {
        handle.await?;
    }
    
    StepResult::Completed
}
```

### 2. 元认知优化器（cognitive/meta_controller/optimizer.rs）

**现状**：仅记录日志，未实际优化。

**优化方案**：

```rust
// 原代码
fn optimize(&mut self, task: &str) -> StepResult {
    log::info!("优化请求: {}", task);
    // 仅记录日志，未实际修改配置
    StepResult::Completed
}

// 优化为：配置修改 + 快照回滚
fn optimize(&mut self, task: &str) -> StepResult {
    log::info!("优化请求: {}", task);
    
    // 1. 获取当前配置快照
    let snapshot = self.config_manager.get_snapshot();
    
    // 2. 根据优化策略修改配置
    let optimized_config = self.apply_optimizations(snapshot);
    
    // 3. 回滚到快照（如果优化失败）
    if !self.validate(&optimized_config) {
        self.config_manager.rollback(&snapshot);
    }
    
    // 4. 应用优化后的配置
    self.config_manager.apply(optimized_config);
    
    StepResult::Completed
}
```

### 3. Swarm 动态超时（agent/swarm/swarm_dynamic_timeout.rs）

**现状**：超时硬编码 120s，无动态调整。

**优化方案**：

```rust
// 原代码
const TIMEOUT: Duration = Duration::from_secs(120);

fn run(&mut self, task: &str) -> StepResult {
    // 硬编码超时
    let result = tokio::time::timeout(TIMEOUT, execute_task(task)).await;
    // ...
}

// 优化为：p95 历史执行时间学习 + 系统负载加权 + 复杂度/优先级/突发/风险补偿
fn run(&mut self, task: &str) -> StepResult {
    let p95 = self.learn_p95_history();
    let load = SystemExt::load_average();
    let load_factor = load.one_minute / 4.0; // 归一化到 0-1
    let complexity = self.estimate_complexity(task);
    let priority = self.estimate_priority(task);
    let risk = self.estimate_risk(task);
    
    let dynamic_timeout = p95 * (1.0 + load_factor) 
        * (1.0 + complexity / 10.0)
        * (1.0 + priority / 10.0)
        * (1.0 + risk / 10.0);
    
    let result = tokio::time::timeout(dynamic_timeout, execute_task(task)).await;
    
    // ...
}
```

### 4. 前端打包体积优化

**现状**：`tesseract.js` 和 `d3` 体积巨大，首屏加载慢。

**优化方案**：

1. **动态导入**：将 `tesseract.js` 和 `d3` 改为按需加载。
2. **Chunk 拆分**：将 `tesseract.js` 和 `d3` 拆分为单独的 chunk，减少主 bundle 体积。
3. **虚拟列表**：使用 `react-virtuoso` 替代 `react-window`，减少 DOM 节点数。

### 5. 桌面打包脚本优化

**现状**：`build-desktop.sh` 仅适用于 macOS。

**优化方案**：

```bash
# scripts/build-release.sh (macOS/Linux 统一分发)

# 1. 编译 Rust 后端
cd crablet
cargo build --release

# 2. 编译桌面端 sidecar
cd ../desktop
cargo build --release

# 3. 复制 sidecar 二进制
# macOS ARM64 sidecar
cp target/release/crablet target/release/crablet-aarch64-apple-darwin
# macOS Intel sidecar
cp target/release/crablet target/release/crablet-x86_64-apple-darwin
# Linux
cp target/release/crablet target/release/crablet-x86_64-unknown-linux-gnu
```

## 总结

Crablet 智能体效果优化核心思路：

1. **工作流引擎**：从空壳到 DAG 拓扑排序 + 并行执行
2. **元认知优化器**：从仅记录日志到配置修改 + 快照回滚
3. **Swarm 动态超时**：从硬编码 120s 到 p95 学习 + 系统负载加权
4. **前端打包体积**：通过动态导入 + Chunk 拆分 + 虚拟列表，大幅减少
5. **桌面打包脚本**：统一支持 macOS DMG / Windows NSIS / Linux AppImage / DEB
