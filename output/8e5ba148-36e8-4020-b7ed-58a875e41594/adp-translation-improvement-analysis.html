🔴 关键缺失（Critical）

C1. 零测试覆盖

Critical 影响：回归风险极高

现状：adp-translation 无任何测试文件。每次改动都可能引入静默回归。

Generator 做法：69 个测试文件，覆盖率底线 62%，pytest + hypothesis 属性测试，guard marker 防止已知 bug 回归。

改进建议：

  • 至少为 check_structure.py、helper.py、lke_client.py 编写单元测试
  • 引入 pytest + pytest-cov，设定覆盖率底线（初始 30%，逐步提升至 60%）
  • 对 helper.py 的节点工厂方法做属性测试（hypothesis）：随机组合节点构建工作流，确保序列化不出错
  • 对 lke_client.py 的签名算法做对照测试（与腾讯云 SDK 输出比对）

C2. 无项目配置与依赖锁定

Critical 影响：环境不可复现

现状：既无 pyproject.toml 也无 requirements.txt。任何人 clone 后不知道该装什么。

Generator 做法：pyproject.toml 定义了运行依赖（openpyxl≥3.0）和 dev 依赖（pytest/ruff/black/mypy/pre-commit），并通过 setuptools 提供 CLI 入口。

改进建议：

  • 创建 pyproject.toml，声明 Python≥3.9 和运行依赖
  • 将 dev 依赖放入 [project.optional-dependencies] dev
  • 注册 CLI 入口：adp-sync, adp-pull, adp-list, adp-trace, adp-audit
  • 添加 .gitignore（排除 dist/, __pycache__, .coverage 等）

C3. 无 CI/CD 流水线

Critical 影响：无自动化质量守卫

现状：无 GitHub Actions / Makefile / pre-commit hooks。

Generator 做法：.github/workflows/ + Makefile（lint/test/coverage/bump）+ .pre-commit-config.yaml。

改进建议：

  • 创建 .github/workflows/ci.yml：lint → test → coverage check
  • 创建 Makefile：make lint, make test, make coverage
  • 添加 .pre-commit-config.yaml：ruff + black + isort

V1. check_structure.py 规则需要模块化拆分

High 影响：可维护性差，新增规则困难

现状：_adp_health() 约 600 行，所有规则堆在一个函数里。

Generator 做法：canvas_sanitizer_lib/ 下拆分为 control_flow_rules / drift_rules / input_rules / reference_rules / ui_lib / xlsx_rules 六个独立模块。

改进建议：

  • 将 _adp_health() 拆分为独立规则模块：rules/control_flow.py, rules/reference.py, rules/ui.py 等
  • 每条规则返回结构化结果：{rule_id, severity, message, fix_hint}
  • 增加规则注册机制，方便后续新增规则

V2. 缺少 golden_gate 级别的推送前全量校验

High 影响：推送后才发现问题，回滚成本高

现状：audit_workflow_refs.py 仅检查 UUID 占位符这一条规则。

Generator 做法：golden_gate_validator 有数十条规则：proto 版本、必需 XLSX、UUID 格式、scene 断言、residue 家族、fallback 节点合法性等。

Translation 应补充的规则：

  • proto 版本校验：确保 DialogJson 版本号与平台一致
  • 必需 XLSX 检查：确保工作流包包含所有必需的 XLSX 文件
  • UUID 格式校验：不仅是占位符，还要检查格式合法性
  • 节点连通性校验：确保 START→END 有可达路径
  • OPTION_CARD 分支一致性：Options 数量与 NextNodeIDs 匹配
  • LOGIC_EVALUATOR 分支完整性：Group/Compound 结构正确
  • residue 残留检测：builder 生成的占位文案未被替换

V3. 缺少跨工作流一致性校验

High 影响：多工作流协作时的交叉引用错误无法捕获

现状：完全缺失。

Generator 做法：topology_consistency.py + parameter_remap.py + architecture_health.py + family_health_share.py。

Translation 应补充：

  • WORKFLOW_REF 目标存在性：引用的子工作流确实存在于同一 App 下
  • ITERATION/BATCH 循环体完整性：循环引用的工作流拓扑正确
  • 变量引用一致性：跨工作流的变量名/类型一致
  • 知识库绑定完整性：RAG 节点绑定的 KB ID 有效

V4. 缺少 residue 残留检测与自动擦除

Medium 影响：builder 生成的占位文案可能残留到生产

Generator 做法：deep_residue_eraser.py 检测并擦除 builder 生成的占位文案残留（如 "TODO:", "{{placeholder}}" 等）。

Translation 应补充：在 helper.py 的节点工厂方法中增加 residue marker 标注，并在 sync_workflows.py 推送前增加 residue 扫描步骤。

⚙️ 工程规范差距

E1. 无代码风格与静态分析配置

High

Generator 做法：pyproject.toml 中配置了 black (line-length=120)、ruff (E/F/I/UP)、isort (profile=black)、mypy (warn_return_any)。

Translation 应补充：

  • ruff 配置：lint + format
  • mypy 配置：至少对 lke_client.py 和 helper.py 做类型检查
  • .pre-commit-config.yaml：自动在 commit 时跑 lint

E2. helper.py 缺乏类型注解与输入校验

Medium

现状：H 类的方法大多无类型注解，也不校验输入合法性。

Generator 做法：adp_canvas_utils.py 有完善的类型注解和 slot 解析。

改进建议：

  • 为所有 H.build_*_node() 方法增加参数类型注解
  • 增加输入校验：node_id 必须是合法 UUID、next_node_ids 不能为空列表（除 END 节点）
  • multi_lang_text() 应校验至少有一种语言非空

E3. lke_client.py 错误处理不够精细

Medium

现状：LKEAPIError 仅携带 action + response，无结构化的错误码分类。

Generator 做法：更细粒度的错误分类（可重试错误 vs 业务逻辑错误 vs 权限错误），配合指数退避重试。

改进建议：

  • 增加 LKERetryableError / LKEAuthError / LKENotFoundError 子类
  • 对 500300（并发冲突）等可重试错误增加指数退避重试
  • 增加请求级别的超时和重试配置

E4. sync_workflows.py 缺少 dry-run 对比报告

Medium

现状：dry-run 仅写 JSON 到 dist/，不做 diff。

Generator 做法：build_proof.py 生成构建证明，对比前后差异。

改进建议：dry-run 时增加 diff 报告：新增/修改/删除的节点、属性变化明细。

E5. 缺少版本管理与 changelog

Low

Generator 做法：bump_skill_version.py + _meta.json 版本追踪。

Translation 应补充：_meta.json 版本元数据 + CHANGELOG.md。

🏗️ 架构演进建议

Translation 现有优势（值得保留）

  • examples/ 目录：10 种场景的示例工作流 + README，Generator 反而缺这个
  • pitfalls/ 文档：按生命周期（build-time / push-time / runtime / ui-render）组织的踩坑记录
  • drift 检测：list_workflows.py 能检测后台手改，Generator 无此功能
  • SSE 追踪：trace_workflow.py 能追踪实际执行过程，Generator 无此功能
  • RAG 知识库绑定：setup_knowledge.py 交互式配置，Generator 无此功能
  • 变量管理：setup_vars.py 批量创建 + 去重，Generator 无此功能
