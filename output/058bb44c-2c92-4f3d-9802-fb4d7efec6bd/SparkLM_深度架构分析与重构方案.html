1. 整体架构概览

SparkLM 是一个多模态/多范式小型语言模型框架，融合了 DeepSeek V4 的 MLA/CSA/HCA/MoE/MTP、NanoGPT 极简风格与 SmolLM 设计哲学。项目已采用 src/ 布局和 pyproject.toml，整体方向正确。但随着功能快速扩张，出现了大量架构层次不清晰、模块边界模糊、包发布机制残缺的问题。

项目规模快照

📦 源码文件
src/sparklm/ 下 ~50+ .py 文件，总代码量 ≈ 700KB，混杂在同一扁平命名空间
🔗 CLI 入口
11 个 console_scripts，但 CLI 目录下有 20+ 脚本，部分未注册为 entry_point
🧠 注意力变体
MLA / GQA / CSA / HCA / Hybrid / SAHA — 6 种机制散落在 4+ 文件中，缺少统一 Protocol
🏋️ 训练脚本
pretrain / sft / dpo / grpo / ppo / vlm / agent / distillation / lora — 9 个 train_*.py，共享逻辑高度重复

核心结论： 项目已初步具备 src-layout + entry_points 骨架（良好起点），但 硬依赖 torch 导致 pip install 在无 GPU/轻量环境必然失败；模块内部存在双向循环依赖与"巨石文件"；训练层 9 个几乎等价的入口脚本违反 DRY 原则，造成维护地狱。

3. 核心问题诊断

P1 — PyPI 发布障碍

问题 1：torch 作为硬依赖，PyPI 安装不可用 Critical

pyproject.toml 把 torch>=2.1.0 列为 dependencies（核心依赖），但 PyPI 上的 torch 版本与 CUDA 版本强绑定。用户在不同 CUDA 环境下 pip install sparklm 会：

  • CPU 环境装到 CPU-only torch（不可用于 GPU 训练）
  • CUDA 12.x 环境装到错误版本
  • 苹果 MPS 环境 torch 无法通过 PyPI 正常解析

正确做法：参考 HuggingFace transformers/trl，将 torch 降为 [project.optional-dependencies] 或在文档中标注"请先按官方指引安装 PyTorch"。

问题 2：requirements.txt 与 pyproject.toml 双重真相 High

同时维护两个依赖声明文件，版本极易漂移，自动化 CI/CD 会随机拉到不同版本树。

问题 3：版本号硬编码 + __version__ fallback 错误 Medium

__init__.py 的 fallback 写的是 "0.3.0" 但 pyproject.toml 版本是 "0.4.0"，开发态 editable install 时二者不一致，importlib.metadata 查不到会静默使用错误版本号。

P2 — 架构层次问题

问题 4：顶层命名空间过于扁平，无层次 Critical

50+ 文件全部平铺在 sparklm/ 下，其中技术上无关的模块（mobilellm_innovations.py、sparklm_tiny.py、innovations.py、causal_routing_smoothing.py、muonclip.py）与核心模型平级共存，没有任何子包分组。

问题 5："巨石"文件 High

文件行数问题
config.py969单一 dataclass 承载所有架构变体的全部参数，验证逻辑与业务逻辑耦合
training/train_pretrain.py~1200+单文件包含数据加载 + 模型构建 + 优化器 + 训练循环 + 评估 + 保存
data/common.py905通用工具函数与格式转换逻辑混杂，难以单独测试
training/train_grpo.py~1300+GRPO 算法、奖励、采样全混在一个文件
vlm.py29KBVLM 模型定义与训练辅助逻辑共存

问题 6：双向依赖与导入副作用 High

model_sparklm.py 直接在顶层 import ECKVCLayer（from expert_kv_compression.py），而 expert_kv_compression.py 又依赖 moe_v4.py 中的 MoE 抽象，形成横向耦合。任何一处修改都可能引起连锁失败。

问题 7：两套 MoE 实现共存，废弃路径不清晰 High

feedforward.py 中的 MoEFeedForward 被标注为 deprecated，但仍出现在 __all__ 和 __init__.py 公开 API 中。moe_v4.py 的 HybridMoELayer 才是当前路径，但文档和示例没有同步更新。

问题 8：Config 职责过重 Medium

SparkLMConfig 是一个 @dataclass，但同时负责：参数存储、多架构变体验证（200+ 行 validate()）、参数量估算、硬件需求估算、launch profile 生成。违反单一职责原则，且验证逻辑中 import warnings 在函数体内部——说明最初没有预料到这里会变成一个"大杂烩"。

问题 9：训练入口脚本高度重复 High

9 个 train_*.py 每个都各自重复：argparse 解析、设备初始化、分布式设置、优化器创建、LR 调度、checkpoint 保存。training/base.py 已经提取了部分共享代码，但各 trainer 仍然大量 copy-paste 其 main() 结构。

P3 — 可维护性问题

问题 10：sparklm_tiny.py 是孤立的平行实现 Medium

TinyRMSNorm 继承 RMSNorm，TinyRoPE 继承 RotaryEmbedding，但整个 sparklm_tiny.py 中仍然有大量从 components.py 独立 copy 出来的代码。这个文件应该成为一个 zoo/ 或 experimental/ 子包，而不是和主模型平级。

问题 11：eval 子包几乎是空壳 Medium

eval/__init__.py 只导出 EvalRunner，eval/metrics/ 是空目录，eval/report.py 仅 1KB。但 CLI 中有 4 个不同的 eval 脚本（evaluate.py、eval_benchmark.py、eval_adv_cot_ppl.py、eval_toolcall.py），形成"两套评估系统"并行的局面。

# nn/attention/base.py
from typing import Protocol, runtime_checkable, Optional, Any, Tuple
import torch
from torch import Tensor

@runtime_checkable
class AttentionProtocol(Protocol):
    """所有注意力实现必须满足的接口契约。"""
    def forward(
        self,
        hidden_states: Tensor,
        cos: Optional[Tensor],
        sin: Optional[Tensor],
        past_key_value: Optional[Any] = None,
        use_cache: bool = False,
        attention_mask: Optional[Tensor] = None,
    ) -> Tuple[Tensor, Optional[Any]]: ...

# nn/attention/__init__.py — 统一注册点
from sparklm.core.registry import ATTENTION_REGISTRY

def register_all_attention_types():
    """在包 import 时一次性注册所有注意力类型。"""
    from .gqa import GroupedQueryAttention
    from .mla import MultiHeadLatentAttention
    from .saha import SharedKAttention
    from .v4.csa import CompressedSparseAttention
    from .v4.hca import HeavilyCompressedAttention

    ATTENTION_REGISTRY.register("gqa",  lambda idx, cfg: GroupedQueryAttention(cfg))
    ATTENTION_REGISTRY.register("mla",  lambda idx, cfg: MultiHeadLatentAttention(cfg))
    ATTENTION_REGISTRY.register("saha", lambda idx, cfg: SharedKAttention(idx, cfg))
    ATTENTION_REGISTRY.register("csa",  lambda idx, cfg: CompressedSparseAttention.from_config(cfg))
    ATTENTION_REGISTRY.register("hca",  lambda idx, cfg: HeavilyCompressedAttention.from_config(cfg))

7.3 BaseTrainer 抽象（消灭 9 个重复的 train_*.py）

# training/base.py（强化现有骨架）
class BaseTrainer(ABC):
    """所有 SparkLM 训练器的基类。
    
    子类只需实现：build_dataset(), build_model(), compute_loss(), step_log()
    其余（设备初始化、DDP、优化器、LR 调度、checkpoint、进度显示）由基类统一处理。
    """
    def __init__(self, args: Namespace): ...
    
    @abstractmethod
    def build_dataset(self) -> torch.utils.data.Dataset: ...
    
    @abstractmethod
    def compute_loss(self, batch) -> dict: ...
    
    def train(self) -> None:
        """通用训练循环。"""
        self._setup()
        dataset = self.build_dataset()
        loader = self._build_loader(dataset)
        model = self._build_model()
        optimizer, scheduler = self._build_optimizer(model)
        for step, batch in enumerate(self._epoch_iter(loader)):
            loss_dict = self.compute_loss(batch)
            self._backward(loss_dict["loss"], optimizer, scheduler)
            if self._should_log(step): self._log(step, loss_dict)
            if self._should_ckpt(step): self._save(step, model)

# training/pretrain.py — 只需 60 行
class PretrainTrainer(BaseTrainer):
    def build_dataset(self):
        return PretrainDataset(self.args.data_path, ...)
    
    def compute_loss(self, batch):
        out = self.model(batch["input_ids"], labels=batch["labels"])
        return {"loss": out["loss"], "aux_loss": out["aux_loss"]}

def main():
    args = parse_pretrain_args()
    PretrainTrainer(args).train()

7.4 延迟 torch import（支持无 GPU 环境安装）

# src/sparklm/__init__.py — 精简版本
"""SparkLM: Next-generation small language model framework."""
from sparklm.version import __version__

# 不在顶层 import torch！
# 用户代码需要 torch 时才触发实际导入：
#   from sparklm.core import SparkLMForCausalLM  ← 此时才 import torch

def __getattr__(name: str):
    """按需 lazy-load，避免 import sparklm 触发 torch 加载。"""
    _CORE = {"SparkLMConfig", "SparkLMModel", "SparkLMForCausalLM", ...}
    if name in _CORE:
        from sparklm.core import model as _m
        return getattr(_m, name)
    # ... 其他 lazy 分组
    raise AttributeError(f"module 'sparklm' has no attribute {name!r}")
