# 历史产物与临时文件清理实施方案

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**目标：** 在不误删当前代码、数据、实验依据或正在运行任务的前提下，分阶段清理缓存、临时下载、实验输出和历史产物。

**方案：** 采用“只读盘点 → 生成候选清单 → 用户确认 → 可恢复隔离 → 校验 → 可选永久删除”的流程。Git 跟踪文件、当前工作树改动、数据集、模型依赖和正在运行的实验默认保护；只有用户确认的精确路径才允许进入清理范围。

**工具：** Git、macOS 进程/文件检查工具、Shell 文件操作；必要时使用项目已有的校验脚本验证数据和实验产物。

## 清理边界

### 默认必须保留

- 所有 Git 已跟踪文件。
- 当前 `git status` 中的修改文件和新增文件，包括配置、脚本、测试和文档。
- `data/`、`paper/`、`PIDray/`、`vendor/`、`templates/`，除非后续单独确认数据集或依赖清理范围。
- 正在运行的训练/评测目录，以及被当前脚本、配置或文档明确引用的 checkpoint。
- `scripts/archive/`、`docs/archive_reports/` 和 `experiments/` 中的历史研究材料；它们虽是历史产物，但仍属于版本库内容。

### 首轮可考虑清理

- Python 缓存：各源码、测试和脚本目录下的 `__pycache__/`、`*.pyc`、`.mypy_cache/`、`.pytest_cache/`、`.ruff_cache/`。
- 工具和系统临时文件：`.DS_Store`、`.session_tmps/`、空的 `.benchmarks/`、已生成的 `src/open_vision_banana.egg-info/`。
- 已验证无用的临时下载压缩包，例如 `tmp_downloads/Priv_personpart.tar`；只有在确认解压内容完整且不再需要重新分发/校验后才处理。

### 需要单独确认

- `output/` 下任何 checkpoint、LoRA、optimizer、feature cache、评测结果、可视化图片和日志。
- `wandb/` 本地运行目录。
- `.dumate/`、`.qoder/`、`.workbuddy/` 等工具状态。
- `docs/`、`scripts/`、`experiments/` 中的旧版本报告、旧脚本和历史实验记录。

## 分阶段执行步骤

### 阶段 0：建立清理快照

**目的：** 为后续审查和回滚保留基线；本阶段只读。

1. 记录 `git status --short`、`git diff --stat` 和未跟踪文件清单。
2. 记录候选目录的路径、文件数量、大小、最后修改时间和是否被 Git 跟踪。
3. 用 `ps` / `pgrep` / `lsof` 检查是否有 Python、torchrun、Accelerate、DeepSpeed 或评测进程使用候选路径。
4. 生成清理清单，至少包含 `output/` 的一级实验目录、每个目录的大小、最近修改时间、checkpoint 数量、日志/指标文件和引用来源。
5. 如果仍有任务写入某个目录，将该目录标记为 `PROTECTED_ACTIVE`，不进入候选删除列表。

**验收：** 快照能解释每个候选路径的来源和保护原因；当前活动评测目录已明确标记。

### 阶段 1：保守清理可重建缓存

**目的：** 回收低风险缓存，不触碰实验结果和数据集。

1. 根据阶段 0 快照确认没有进程正在写入缓存目录。
2. 将用户确认的缓存目录移动到带时间戳的隔离目录，而不是直接 `rm -rf`。
3. 对隔离后的目录执行文件数量和大小复核。
4. 运行一次最小导入或测试前置检查，确认 Python 包仍能发现源码；缓存应允许重新生成。

**默认候选：** `__pycache__/`、`*.pyc`、`.mypy_cache/`、`.pytest_cache/`、`.ruff_cache/`、`.session_tmps/`、`.DS_Store`、空的 `.benchmarks/`、`src/open_vision_banana.egg-info/`。

**验收：** `git status --short` 不出现意外的源码、配置、测试或文档删除；缓存目录可在需要时重新产生。

### 阶段 2：核对并清理临时下载

**目的：** 优先处理 `tmp_downloads/` 中可以从已解压内容或公开来源恢复的压缩包。

1. 对每个压缩包确认解压目录存在，并比较归档文件列表和解压后的文件数量。
2. 查找脚本和配置是否仍把该压缩包作为输入；不能仅凭文件名判断无用。
3. 对确认不再需要的压缩包先移动到隔离目录，保留原始相对路径记录。
4. 由用户确认后再永久删除隔离副本；若仍需长期保留，移出仓库并记录外部存储位置。

**首个候选：** `tmp_downloads/Priv_personpart.tar`。解压目录 `tmp_downloads/priv_personpart_extracted/` 必须先通过完整性核对；解压目录本身不自动删除。

**验收：** 相关数据准备脚本仍能找到已保留的输入；需要时可从解压目录或外部归档恢复。

### 阶段 3：建立实验输出保留策略

**目的：** 在 `output/` 中区分可复现实验依据、可恢复 checkpoint 和纯临时结果。

对每个一级实验目录建立以下字段：

| 字段 | 用途 |
| --- | --- |
| 实验目录和大小 | 估算可回收空间 |
| 最近修改时间 | 识别当前/近期实验 |
| 是否有活动进程 | 防止删除正在写入的结果 |
| 是否被脚本、配置、文档引用 | 防止破坏复现入口 |
| 最佳/最终 checkpoint | 决定最低保留集 |
| optimizer、feature cache、中间 checkpoint | 判断是否还能支持 resume |
| metrics、report、config、log | 保留实验结论和复现上下文 |

建议的单实验保留集：

- 运行配置、参数、指标 JSON、最终报告和关键日志。
- 一个明确标记的 `best` 或 `final` checkpoint。
- 仍计划继续训练的实验保留 optimizer 和 resume checkpoint。
- 仅用于可视化的 PNG、重复评测结果和中间 checkpoint，只有在确认不再需要后才清理。

特别注意：

- 当前活动目录 `output/flux_schnell_paper_gate_lr1e5_20260824/` 全部保护。
- `output/` 中的 `feature_cache/*.pt` 可能体积很大但可重建；是否删除取决于是否还要复用相同特征缓存，不能自动处理。
- 不按 `smoke`、`old`、日期或 UUID 单一命名模式批量删除；实验名称可能仍被脚本或文档引用。

### 阶段 4：处理本地 W&B 和工具状态

1. 确认 W&B 运行记录已同步到远端，或确认用户不需要本地离线记录。
2. 关闭相关训练/评测工具后，再将 `wandb/` 下已完成运行的本地目录移入隔离区。
3. `.qoder/`、`.dumate/`、`.workbuddy/` 分开处理：先确认其中没有需要保留的会话、索引、记忆或项目元数据，再决定是否清理。
4. 如这些目录确实是本机专用状态，后续可补充 `.gitignore` 规则；不在清理阶段擅自修改规则。

### 阶段 5：历史版本材料的独立审查

这一步不属于首轮物理清理，必须单独确认：

1. 对 `scripts/archive/`、`docs/archive_reports/`、旧版本分析报告和 `experiments/` 建立引用关系。
2. 保留仍被 README、路线报告、ADR、测试或实验脚本引用的文件。
3. 对重复报告优先保留最新结论、原始证据索引和必要的变更记录。
4. 若要删除 Git 跟踪的历史材料，单独创建提交并在提交说明中列出删除清单和恢复方式；不得和运行时缓存清理混在一次不可逆操作中。

## 回滚与安全要求

- 首选“移动到隔离目录”，隔离目录使用明确的绝对路径和时间戳命名。
- 每次移动前输出待处理的精确路径清单，禁止对仓库根目录、`output/` 或 `data/` 使用未经展开的递归删除通配符。
- 任何路径若同时出现在 Git diff、活动进程参数、配置或脚本引用中，自动升级为 `PROTECTED`，等待人工确认。
- 隔离后的内容至少保留一个审查周期；只有用户再次确认后才永久删除。
- 永久删除前报告实际回收空间、文件数量和剩余隔离位置。

## 推荐执行顺序

推荐先执行保守范围：

1. 阶段 0：快照和活动任务检查。
2. 阶段 1：可重建缓存和系统临时文件。
3. 阶段 2：只删除已验证的临时压缩包，暂不删除解压数据。
4. 阶段 3：只生成 `output/` 保留候选清单，不删除任何实验目录。
5. 阶段 4、5：等候用户对 W&B、工具状态和历史 Git 材料分别确认。

这样可以先低风险回收约 185M 缓存空间，并可能回收临时压缩包空间，同时为后续 `output/` 的大规模清理保留可审计的决策依据。
